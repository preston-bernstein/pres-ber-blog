## CLAUDE.md

This repo's CLAUDE.md defines a mandatory "Voice contract" for any blog post
drafting (routes through /voice-draft, out of scope for this feature — it
builds the pipeline only, not real link-post content) and a "GEO content
contract" of 8 rules enforced by `scripts/geo-gate.py` in CI. The gate runs
after `hugo --gc --minify` in CI, before FTP deploy on `main`; a failure
blocks deploy. Confirmed by direct inspection: its checks hard-glob
`content/english/blog/*.md` and `public/blog/*/index.html` only, so a new
`content/english/links/` section is outside its scope by construction.

## Additional real facts (verified in-repo, not assumed)

- Hugo Extended v0.164.0, pinned identically in `.github/workflows/main.yml`
  and `geo-gate.yml`. Local brew Hugo matches this exactly as of this run.
- Theme: Blowfish (github.com/nunocoracao/blowfish), vendored as a **public**
  git submodule at `themes/blowfish` (plain HTTPS, no credential).
  `layouts/_default` is nearly empty — Blowfish's own theme layouts provide
  almost all rendering today.
- `content/english/` has: `blog/`, `authors/`, `pages/`, `contact/`. `data/`
  has `authors/` and `geo-battery.json` — both non-Hugo-native external data
  files, an established precedent for `data/linkposts.json`.
- `hugo.toml` sets `[outputs] home = ["HTML","RSS","JSON","llms"]` with no
  `[outputs.section]` override — a new `content/english/links/` section will
  auto-generate `/links/index.xml` via Hugo itself unless disabled per-section.
- `package.json` scripts: `dev`, `build` (`hugo --gc --minify
  --templateMetrics --templateMetricsHints --forceSyncStatic`), `test`
  (playwright). No Python tooling in CI today — `scripts/geo-gate.py` is the
  only Python in this repo and is stdlib-only (zero pip installs in CI).
- linkblog-commons (github.com/preston-bernstein/linkblog-commons) is
  **private**. Its actual CLI (confirmed against its real `cli.py`, written
  earlier this session): `python -m linkblog_commons render --url --published
  --comment [--tag ...] --output-dir <dir>` (flags, not JSON/stdin) and
  `python -m linkblog_commons feed --input <path-or-"-"> --output <path>
  --title --link [--id]`. Both print a JSON status envelope to stdout.
  `hugo_render()`'s front matter uses `published`, not Hugo's native `date`
  field — Blowfish's templates rely on `.Date`, so `build-linkblog.py` must
  inject a `date` field into each rendered file after linkblog-commons writes
  it (linkblog-commons itself is out of scope to modify).
- CI deploy: `.github/workflows/main.yml` triggers on push to `main`, runs
  `npm run build`, then `python3 scripts/geo-gate.py`, then Playwright tests,
  then FTP-deploys `public/` to the live site. No staging environment — push
  to `main` is the live deploy.
- MERGE_MODE for this repo: `direct` (recent commit history is linear direct
  commits to `main`, not PR-based; last merged PR was 2026-07-19).
