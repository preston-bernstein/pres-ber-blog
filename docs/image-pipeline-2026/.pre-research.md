- GAP: the research doc recommends Hugo's OFFICIAL render-hook mechanism for Mermaid — a fenced ```mermaid code block handled by a `layouts/_default/_markup/render-codeblock-mermaid.html` override (Hugo's per-language codeblock hook naming convention) — because fenced code blocks are the portable Markdown convention vs. a Hugo/Blowfish-only shortcode. RECONCILE, don't replace: reuse Blowfish's already-working vendored mermaid.min.js + theme-aware mermaid.js config (no new CDN dependency, no duplicate JS) — just add the code-fence entry point on top of it.
- KNOWN TEMPLATE-ORDERING HAZARD (verified): themes/blowfish/layouts/_default/baseof.html calls `partial "head.html" .` BEFORE `<body>`; single.html only calls `.Content` well into the body. A `.Page.Store`-based "hasMermaid" flag set inside a render hook (which only fires when `.Content` is actually rendered) is NOT yet populated when head.html/vendor.html runs — a naive Store-flag approach silently fails to load the JS. The reliable fix: check `.RawContent` (raw, unrendered Markdown, available without forcing a full content render) for the literal ```` ```mermaid ```` marker. Hugo's own `.Page.HasShortcode` avoids this hazard because shortcode-usage tracking happens during Markdown parsing, independent of the lazy `.Content` render.
- The theme has TWO documented, already-proven-safe extension points confirmed in this repo (used successfully by other passes today): layouts/partials/extend-head.html / extend-footer.html (partialCached, renders ONCE and reuses across ALL pages — do NOT use for anything page-conditional) vs. layouts/partials/extend-head-uncached.html (checked via `templates.Exists` + plain `partial` in themes/blowfish/layouts/partials/head.html around line 220 — NOT currently present at site level, safe to add, re-evaluates per page). Prefer adding a new, surgical layouts/partials/extend-head-uncached.html that emits the same Mermaid `<script>` tag pattern vendor.html already uses (same resources.Get/Concat/Fingerprint calls) gated on `(or (.Page.HasShortcode "mermaid") (in .RawContent "` + "```mermaid" + `"))`, rather than duplicating/overriding the entire vendor.html partial (DRY — vendor.html has ~9 unrelated other shortcode-loading blocks).
