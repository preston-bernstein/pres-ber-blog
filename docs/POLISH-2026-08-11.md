## What was applied

### Live bugs fixed (found during the Elegance/Architecture lens's real-build verification)

- **Blog pagination was silently broken** — `hugo.toml`: `paginate = 15` is Hugo's pre-0.128 key; Hugo 0.164.0 (this repo's pinned CI version) ignores it and falls back to the framework default of 10/page. The site was shipping 3 pages of ~8 posts instead of 2 pages of 15, since commit `3ff2a20` ("Raise blog index pagination from 2 to 15") was written. Fixed with `[pagination]\npagerSize = 15`. Verified: rebuilt, `/blog/page/1,2` (was `/blog/page/1,2,3`).
- **A dead Google Analytics placeholder fired on every pageview** — `hugo.toml`: `[services.googleAnalytics] ID = 'G-MEASUREMENT_ID'` was a literal, never-replaced placeholder. Verified in built HTML: every page shipped a request to `googletagmanager.com/gtag/js?id=G-MEASUREMENT_ID` alongside the real, working GTM tag. Removed — GTM already covers analytics.
- **SEO meta description and social-card image were both missing site-wide** — `config/_default/params.toml`: the SEO block was nested under `[metadata]` (Hugoplate's shape); Blowfish reads `description`/`keywords`/`defaultSocialImage` as bare top-level `Site.Params` keys. Verified: built `index.html` had no `<meta name="description">` and no `og:image`/`twitter:image` at all before the fix, both present after. Caught the exact TOML "bare key after a `[table]` header gets silently reparented" footgun once myself mid-fix (this file's own comments warn about it) — caught by re-verifying against a real build before moving on, not by trusting the diff alone.
- **`npm test` crashed outright** — `jasmine.json`'s `spec_dir: ""` + glob swept in the Playwright specs under `tests/e2e/`, so `npm test` errored immediately. `spec/` only ever contained test-double helpers (jsdom/sinon setup) with zero actual Jasmine spec files — the harness had no real coverage to lose. Deleted the whole Jasmine harness (`jasmine.json`, `spec/`, the `jasmine`/`jasmine-*-reporter`/`jsdom`/`sinon` devDeps) and repointed `"test"` at `playwright test` — the only test suite with real, passing coverage (17 specs across dark-mode, reading-progress-bar, blog-post-content, toc-scrollspy).
- **CI never ran any tests before deploying** — `.github/workflows/main.yml` went straight from `npm run build` to the FTP deploy step, even though real Playwright coverage existed. A regression in dark-mode, the reading-progress-bar, TOC scrollspy, or blog content could ship straight to production (no staging environment) with zero pre-deploy signal. Added `npx playwright install --with-deps chromium` + `npm test` as required steps before deploy.
- **Hugo deprecation**: `[imaging].quality` (top-level) was deprecated in Hugo v0.163.0; split into `[imaging.jpeg].quality` / `[imaging.webp].quality`.
- **Stale copyright year**: `config/_default/params.toml` hardcoded "© 2024"; switched to Blowfish's own `{ year }` placeholder token (the same mechanism `layouts/partials/footer.html` and `layouts/_default/rss.xml` already use via `replace .Site.Params.copyright "{ year }" now.Year`), not a template expression — verified this distinction against the actual theme source after nearly getting it wrong.
- **`_redirects`**: the 404 fallback pointed at `/en/404.html`, which the actual build never produces (`defaultContentLanguageInSubdir = false` → `/404.html` at root). Fixed the path.

### Dead files removed (Hugoplate→Blowfish migration leftovers, commit `0935a02`)

All confirmed via grep across this repo's own layouts *and* the Blowfish theme's actual submodule source (checked out fresh for this pass — it wasn't initialized locally before), plus real `hugo build` runs showing no change in output:

- `theme.toml` — described this personal blog as a distributable Hugo theme, misattributed to Hugoplate/DigitalMast under the wrong license. Hugo never reads a site-root `theme.toml`; Blowfish already carries its own inside the submodule.
- `data/theme.json` — zero references anywhere (own layouts or Blowfish's). Was Hugoplate's theming convention; Blowfish reads appearance config from `params.toml` instead.
- `i18n/en.yaml` — every key used Hugoplate's flat namespace (`toc`, `read_more`); Blowfish uses nested namespaces (`article.table_of_contents`, `search.*`). Zero string collisions confirmed the whole file was inert.
- `config/development/server.toml` — self-contradictory (required `defaultContentLanguageInSubdir = true`, which is `false`) and pointed at the same nonexistent `/en/404.html` path as `_redirects`.
- `.jshintrc` — jshint isn't a devDependency and nothing invokes it; linting is prettier-only.
- `scripts/removeDarkmode.js`, `scripts/clearModules.js`, `scripts/projectSetup.js` (+ their `remove-darkmode`/`update-modules`/`project-setup` npm scripts) — all three are Hugoplate scaffolding operating on paths this repo no longer has (`exampleSite/`, `assets/scss`, `layouts/partials/essentials/`). `removeDarkmode.js` would also actively contradict current site behavior — dark mode is live, wired, and covered by a passing test. `projectSetup.js`'s guard (`!fs.existsSync("themes")`) is permanently false now that Blowfish is a fixed git submodule; confirmed it would crash on `ENOENT` if the guard ever did open, since its target `exampleSite/hugo.toml` doesn't exist.
- The entire Tailwind/PostCSS chain (`tailwind.config.js`, `postcss.config.js`) — Blowfish ships its own precompiled CSS bundle (`resources.Get "css/compiled/main.css"`, confirmed in the theme's own `head.html`); this repo's `assets/` has no CSS/SCSS entry point for Hugo Pipes or PostCSS to process, and no npm script ever invoked either tool. Removed the matching Tailwind-only wiring from `hugo.toml`: the `hugo_stats.json` module mount, `[build.buildStats]`, and the two Tailwind-specific cachebusters (kept the four generic asset cachebusters — those are Hugo's own general-purpose defaults, not Tailwind-specific, and apply correctly if a site-level CSS/JS asset is ever added).
- `hugo.toml`'s `[mediaTypes]`/`[outputFormats.WebAppManifest]`/`[outputFormats.SearchIndex]` blocks — verified via a real build that neither `manifest.webmanifest` nor `searchindex.json` was actually produced by this config (Blowfish's search reads the plain built-in `"JSON"` output format already listed in `[outputs]`, not a custom named format).
- `config/_default/params.toml` dead keys: `navbar_fixed`, `contact_form_action`, `[site_verification]` (Blowfish reads `[verification]` under different sub-keys — commented out as a template rather than deleted, since all codes are currently unset anyway), `[cookies]`, `[mermaid].js_url` (Blowfish bundles its own `mermaid.min.js`), `[widgets]`, `[google_map]`, `[subscription]` — zero references in Blowfish's actual layouts, confirmed via grep against the checked-out submodule.
- `go.sum` (local-only, gitignored) — orphaned Hugo-Modules-era artifact; no `go.mod` exists and the theme is a git submodule, not a Hugo module.

## What was escalated, then resolved on a follow-up pass

**1. Author archive page lists zero posts.** Originally escalated as an open content-architecture decision: `content/english/authors/preston-bernstein/_index.md` is a real content page/section sitting at `/authors/preston-bernstein/`, and Hugo's section lookup (`.Pages` = physically-nested child content, empty here since posts live under `content/english/blog/`) beat the `authors` taxonomy's own post-tagging mechanism, which is unrelated to `.Pages` on a section page. Resolved without new template code, after a concurrent upstream commit (`121d8af`, "Restore signature logo and social-icon footer lost in the theme migration") independently removed the per-post author byline for the same underlying reason: "single-author personal site: identity is already in the nav/footer/home profile on every page" — every post here is by the same one author, so a dedicated "posts by this author" archive is redundant with `/blog/`, the same call upstream already made for the per-post byline. Kept the page as what it now clearly is — a bio/schema.org page, not a post index — and fixed its own stale Hugoplate front matter (`meta_title` is a dead Hugoplate-only key Blowfish never reads; "Meet Our Authors"/plural "talented authors" copy was template boilerplate for a multi-author demo site). The Playwright test that originally caught this (`blog-post-content.spec.js`, "author byline links to a non-empty author archive page") was independently retired by that same upstream commit — current suite (50 specs) has no test asserting a post list here.

**2. The four legacy/alternate deploy configs remain not-fully-functional if ever activated.** `netlify.toml`, `vercel-build.sh`, `.gitlab-ci.yml`, and `amplify.yml` are documented in `readme.md` as intentionally-kept alternates, not the active deploy path — a deliberateness marker this pass respected. Not fixed further since building out untested infrastructure for platforms nobody currently uses is speculative work beyond this pass's scope.
